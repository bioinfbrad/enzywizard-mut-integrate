# EnzyWizard-Mut_Integrate

EnzyWizard-Mut-Integrate is a command-line tool for integrating wild-type and
mutant EnzyWizard JSON reports and constructing matched wild-type / mutant
protein graph representations.
It takes an enzywizard_mut_clean report, a wild-type report
directory and a mutant report directory as input, and merges information
from supported report types into structured paired graph datasets, where nodes
represent residues or substrates, and edges represent molecular interactions.
The input enzywizard_mut_clean report is used as the anchor for cleaned amino acid 
substitution, residue indexing, and wild-type / mutant residue mapping.
Additional reports on each side provide complementary features.
The tool integrates the paired graph data, enabling direct downstream use in
mutation effect analysis, wild-type / mutant graph comparison, graph-based
machine learning, and enzyme engineering studies.

# example usage:

The examples below use placeholder paths such as
`path/to/mut_clean_report_WT_to_MUT.json`, `path/to/wt_reports/`, and
`path/to/mut_reports/`; replace them with your own EnzyWizard JSON report files
and directories. EnzyWizard-Mut-Integrate reads JSON reports generated by
upstream EnzyWizard tools. The wild-type and mutant output directories must be
different directories.

Run the default non-strict workflow with matched wild-type and mutant report
directories. The `enzywizard_mut_clean` report is required and provides the
cleaned mutation, residue mappings, and clean statistics. Other reports in the
two side directories are integrated when present.

```
enzywizard-mut-integrate -i path/to/mut_clean_report_WT_to_MUT.json -w path/to/wt_reports/ -m path/to/mut_reports/ -wo path/to/wt_mut_integrate_output/ -mo path/to/mut_mut_integrate_output/
```

Use long option names for the same non-strict workflow.

```
enzywizard-mut-integrate --mut_clean_report_path path/to/mut_clean_report_WT_to_MUT.json --wt_input_dir path/to/wt_reports/ --mut_input_dir path/to/mut_reports/ --wt_output_dir path/to/wt_mut_integrate_output/ --mut_output_dir path/to/mut_mut_integrate_output/
```

Integrate minimal directories containing no side reports. The output graphs are
empty because no molecular interaction report is available.

```
enzywizard-mut-integrate -i path/to/mut_clean_report_WT_to_MUT.json -w path/to/empty_wt_reports/ -m path/to/empty_mut_reports/ -wo path/to/wt_minimal_output/ -mo path/to/mut_minimal_output/
```

Run a partial integration, for example with aaprops, flexibility,
conservation, pocket, substrate, and interaction reports on each side. In
non-strict mode, missing report types are allowed and the output contains the
fields that can be derived from the reports that are present.

```
enzywizard-mut-integrate -i path/to/mut_clean_report_WT_to_MUT.json -w path/to/partial_wt_reports/ -m path/to/partial_mut_reports/ -wo path/to/wt_partial_output/ -mo path/to/mut_partial_output/
```

Run strict integration for a complete paired report set. Strict mode requires
all supported side report types in both the wild-type and mutant input
directories and also requires all node fields.

```
enzywizard-mut-integrate -i path/to/mut_clean_report_WT_to_MUT.json -w path/to/all_wt_reports/ -m path/to/all_mut_reports/ -wo path/to/wt_strict_output/ -mo path/to/mut_strict_output/ --strict
```

Use a mut-clean report containing multiple substitutions. Multiple cleaned
substitutions are represented in the mut-clean report with semicolons, such as
`S45G;A50V`; the command-line usage is the same.

```
enzywizard-mut-integrate -i path/to/mut_clean_report_WT_to_MUT_S45G_A50V.json -w path/to/wt_reports/ -m path/to/mut_reports/ -wo path/to/wt_multi_site_output/ -mo path/to/mut_multi_site_output/
```


# input parameters:

-i, --mut_clean_report_path
Required.
Path to the `enzywizard_mut_clean` JSON report generated by EnzyWizard-Mut-Clean.
Mut-clean generates this file with the name pattern `mut_clean_report_{wt_protein_name}_to_{mut_protein_name}.json`, and mut-integrate derives output file names from it.

-w, --wt_input_dir
Required.
Path to a directory containing wild-type side-report JSON files to integrate.
Only JSON report files are used.

-m, --mut_input_dir
Required.
Path to a directory containing mutant side-report JSON files to integrate.
Only JSON report files are used.

Supported side report types include:
- enzywizard_aaprops
- enzywizard_hydrocluster
- enzywizard_energy
- enzywizard_flexibility
- enzywizard_disorder
- enzywizard_conservation
- enzywizard_embedding
- enzywizard_pocket
- enzywizard_substrate
- enzywizard_dock
- enzywizard_interaction

Duplicate supported side report types are not allowed on either side, even if the duplicate reports use different file names.

-wo, --wt_output_dir
Required.
Directory to save wild-type mut-integrated JSON outputs.
The directory is created automatically if it does not exist.

-mo, --mut_output_dir
Required.
Directory to save mutant mut-integrated JSON outputs.
The directory is created automatically if it does not exist.

wt_output_dir and mut_output_dir must be different directories.

--strict
Optional.
Enable strict mode. In strict mode, both `wt_input_dir` and `mut_input_dir` must contain all 11 supported side report types; missing any side report type causes an error. By default, strict mode is disabled. In non-strict mode, missing side report types are allowed and the output contains the fields that can be derived from the reports that are present.


# output files:

The program outputs the following files into the output directories:

`{wt_protein_name}` and `{mut_protein_name}` are derived from the
EnzyWizard-Mut-Clean report file name.

1. A mut-integrate JSON report
   - mut_integrate_report_{wt_protein_name}_to_{mut_protein_name}.json
     - Full paired report containing overall statistics, mutation-site
       properties, and wild-type / mutant integrated graph entries. This file
       is saved into both output directories.

2. A wild-type node-only JSON file
   - wt_integrate_nodes_{wt_protein_name}.json
     - Array of wild-type integrated graph node records split from the
       wild-type integrated graph. This file is saved into `wt_output_dir`.

3. A wild-type edge-only JSON file
   - wt_integrate_edges_{wt_protein_name}.json
     - Array of wild-type integrated graph edge records split from the
       wild-type integrated graph. This file is saved into `wt_output_dir`.

4. A mutant node-only JSON file
   - mut_integrate_nodes_{mut_protein_name}.json
     - Array of mutant integrated graph node records split from the mutant
       integrated graph. This file is saved into `mut_output_dir`.

5. A mutant edge-only JSON file
   - mut_integrate_edges_{mut_protein_name}.json
     - Array of mutant integrated graph edge records split from the mutant
       integrated graph. This file is saved into `mut_output_dir`.

6. A log file
   - log.txt
     - Processing log containing informational messages and errors. This file
       is saved into both output directories.

# Process:

This command processes the mutation-paired JSON reports as follows:

1. Validate input paths
   - Check that mut_clean_report_path exists.
   - Check that wt_input_dir and mut_input_dir are valid directories.
   - Check that wt_output_dir and mut_output_dir are different directories.
   - Create output directories if needed.

2. Resolve protein names
   - Parse wild-type and mutant protein names from the mut_clean report filename.

3. Load and validate mut_clean report
   - Read the enzywizard_mut_clean JSON report.
   - Validate its schema and required mutation fields.
   - Confirm that report_type is enzywizard_mut_clean.

4. List side JSON files
   - Search wt_input_dir for wild-type JSON files.
   - Search mut_input_dir for mutant JSON files.

5. Validate report counts
   - Ensure the number of JSON files on each side does not exceed the maximum number of supported side report types.
   - In strict mode, require exactly all supported side report types on both sides.

6. Load and validate wild-type reports
   - Read each JSON report from wt_input_dir.
   - Validate each report using report_type-specific schema checks.
   - Reject unsupported report types for mut_integrate.
   - Reject duplicated report types on the wild-type side.

7. Load and validate mutant reports
   - Read each JSON report from mut_input_dir.
   - Validate each report using report_type-specific schema checks.
   - Reject unsupported report types for mut_integrate.
   - Reject duplicated report types on the mutant side.

8. Synthesize clean reports
   - Generate a synthetic enzywizard_clean report for the wild-type side from mut_clean_report.
   - Generate a synthetic enzywizard_clean report for the mutant side from mut_clean_report.

9. Build full report dictionaries
   - Add synthesized clean reports into the wild-type and mutant report dictionaries.
   - Use these synthesized clean reports as anchor reports for residue indexing.

10. Validate cleaned mutation definition
   - Read cleaned_amino_acid_substitution from mut_clean_report.
   - Extract cleaned residue lists for wild-type and mutant proteins.
   - Validate that the cleaned mutation definition is compatible with the cleaned residue mappings.

11. Build overall statistics
   - Construct paired wild-type / mutant overall statistics.
   - Reorder fields into stable wild_type / mutant / difference output structure.

12. Build amino acid substitution properties
   - Parse mutation positions from cleaned_amino_acid_substitution. Multiple mutation sites are separated by ';'.
   - Match mutation residues in both cleaned residue lists.
   - Extract amino acid substitution properties from available reports, including:
     - amino acid properties
     - flexibility
     - conservation
   - Compute wild_type / mutant / difference amino acid substitution summaries.

13. Build paired integrated graphs
   - Construct wild-type integrated graph from wild-type reports.
   - Construct mutant integrated graph from mutant reports.
   - If interaction reports are missing on either side, return empty integrated graphs.

14. Generate mut-integrate report
   - Assemble cleaned_amino_acid_substitution, overall_statistics, amino_acid_substitution_properties,
     wild_type_integrated_graph, and mutant_integrated_graph into one report.

15. Save mut-integrate report
   - Write the same mut-integrate report into wt_output_dir.
   - Write the same mut-integrate report into mut_output_dir.

16. Split integrated graphs
   - Parse wild_type_integrated_graph into:
     - wild-type node list
     - wild-type edge list
   - Parse mutant_integrated_graph into:
     - mutant node list
     - mutant edge list

17. Save node and edge outputs
   - Save wild-type node and edge JSON files.
   - Save mutant node and edge JSON files.

18. Finalize outputs
   - Finish mut_integrate processing.
   - Copy the generated log file from wt_output_dir to mut_output_dir.


# common errors and solutions:

- "mut_clean_report not found"
  - Cause: The path passed with `-i` or `--mut_clean_report_path` does not exist.
  - Solution: Check the mut-clean report path and pass the JSON report generated by EnzyWizard-Mut-Clean.

- "Invalid wt_input_dir"
  - Cause: The path passed with `-w` or `--wt_input_dir` does not exist or is not a directory.
  - Solution: Check the wild-type side-report directory path and make sure it contains the intended EnzyWizard JSON reports.

- "Invalid mut_input_dir"
  - Cause: The path passed with `-m` or `--mut_input_dir` does not exist or is not a directory.
  - Solution: Check the mutant side-report directory path and make sure it contains the intended EnzyWizard JSON reports.

- "wt_output_dir and mut_output_dir must be different directories."
  - Cause: The same directory was passed for both output sides.
  - Solution: Use two different output directories so the wild-type and mutant split node / edge files do not overwrite each other.

- "Invalid mut_clean_report format"
  - Cause: The input file passed with `-i` is not a valid EnzyWizard-Mut-Clean report.
  - Solution: Regenerate the report with EnzyWizard-Mut-Clean and confirm that its `report_type` is `enzywizard_mut_clean`.

- "mut_clean_report_path must point to an enzywizard_mut_clean JSON file"
  - Cause: The required mut-clean report path points to another EnzyWizard report type.
  - Solution: Pass the EnzyWizard-Mut-Clean report with `-i`, and keep side reports in `wt_input_dir` and `mut_input_dir`.

- "mut_clean_report file name must match"
  - Cause: The mut-clean report file name does not follow the naming pattern generated by EnzyWizard-Mut-Clean.
  - Solution: Use the original mut-clean output file name, because mut-integrate derives output file names from it.

- "Invalid mut_clean_report file name. Cannot find '_to_' separator"
  - Cause: The mut-clean report file name cannot be split into wild-type and mutant protein names.
  - Solution: Use the mut-clean report generated by EnzyWizard-Mut-Clean, or rename the file so it contains the wild-type-to-mutant separator.

- "Invalid amino_acid_substitution in mut_clean report."
  - Cause: The original amino acid substitution string in the mut-clean report is missing or malformed.
  - Solution: Regenerate the mut-clean report with a valid substitution such as a one-letter amino-acid replacement; use semicolons for multiple substitutions.

- "Invalid cleaned_amino_acid_substitution in mut_clean report."
  - Cause: The cleaned substitution string in the mut-clean report is missing, malformed, or inconsistent with the cleaned residue mappings.
  - Solution: Regenerate the mut-clean report from matching wild-type and mutant clean inputs.

- "Invalid report format in wt_input_dir"
  - Cause: A wild-type side JSON file does not match the expected structure for its EnzyWizard report type.
  - Solution: Regenerate the report with the corresponding EnzyWizard tool and check `log.txt` for the first validation error.

- "Invalid report format in mut_input_dir"
  - Cause: A mutant side JSON file does not match the expected structure for its EnzyWizard report type.
  - Solution: Regenerate the report with the corresponding EnzyWizard tool and check `log.txt` for the first validation error.

- "Number of JSON files in wt_input_dir exceeds 12 (maximum allowed report types)"
  - Cause: The wild-type input directory contains more JSON files than the number of supported side report types.
  - Solution: Remove unrelated JSON files and keep at most one JSON report for each supported wild-type side report type.

- "Number of JSON files in mut_input_dir exceeds 12 (maximum allowed report types)"
  - Cause: The mutant input directory contains more JSON files than the number of supported side report types.
  - Solution: Remove unrelated JSON files and keep at most one JSON report for each supported mutant side report type.

- "Duplicate report type found in wt_input_dir"
  - Cause: Two or more wild-type JSON files have the same supported `report_type`.
  - Solution: Keep one wild-type report for each supported report type and move duplicates out of the input directory.

- "Duplicate report type found in mut_input_dir"
  - Cause: Two or more mutant JSON files have the same supported `report_type`.
  - Solution: Keep one mutant report for each supported report type and move duplicates out of the input directory.

- "Unsupported report type in wt_input_dir for mut_integrate"
  - Cause: A wild-type side JSON file has a `report_type` that EnzyWizard-Mut-Integrate does not support.
  - Solution: Remove unsupported JSON files from the wild-type input directory.

- "Unsupported report type in mut_input_dir for mut_integrate"
  - Cause: A mutant side JSON file has a `report_type` that EnzyWizard-Mut-Integrate does not support.
  - Solution: Remove unsupported JSON files from the mutant input directory.

- "Strict mode requires exactly"
  - Cause: `--strict` was enabled, but one side does not contain all supported side report types.
  - Solution: Add the missing side reports on both wild-type and mutant sides, or run without `--strict` when partial integration is intended.

- "Missing required report in strict mode"
  - Cause: A report required by strict mode is missing after the paired report set has been assembled.
  - Solution: Add the missing report, or run without `--strict` for partial wild-type and mutant report directories.

- "Mutation position missing in WT cleaned residue list"
  - Cause: A mutation position from the cleaned substitution string is not present in the wild-type cleaned residue mapping.
  - Solution: Regenerate the mut-clean report from the same cleaned wild-type structure used to build the side reports.

- "Mutation position missing in MUT cleaned residue list"
  - Cause: A mutation position from the cleaned substitution string is not present in the mutant cleaned residue mapping.
  - Solution: Regenerate the mut-clean report from the same cleaned mutant structure used to build the side reports.

- "Missing WT amino_acid_residue_properties entry for mutation site"
  - Cause: A wild-type aaprops report is present, but it does not contain the cleaned mutation-site residue.
  - Solution: Regenerate the wild-type aaprops report from the same cleaned wild-type structure used by the mut-clean report.

- "Missing MUT amino_acid_residue_properties entry for mutation site"
  - Cause: A mutant aaprops report is present, but it does not contain the cleaned mutation-site residue.
  - Solution: Regenerate the mutant aaprops report from the same cleaned mutant structure used by the mut-clean report.

- "Failed to save mut-integrate JSON"
  - Cause: An output JSON file could not be written because of a filesystem, permission, path, or disk-space problem.
  - Solution: Check that both output directories are writable and that there is enough disk space.

- "Failed to copy log.txt to mut_output_dir"
  - Cause: The report files were generated, but copying the log file from the wild-type output directory to the mutant output directory failed.
  - Solution: Check write permission and available disk space for `mut_output_dir`; the main JSON outputs may already exist.

- Output files are missing or fewer than expected.
  - Cause: The command failed before all outputs were written, or one of the output directories is not the directory passed to `-wo` or `-mo`.
  - Solution: Check `log.txt` in `wt_output_dir` first, then check whether the same log was copied to `mut_output_dir`.

- Output file names do not match the expected protein names.
  - Cause: Output file names are derived from the EnzyWizard-Mut-Clean report file name and then sanitized for filesystem safety.
  - Solution: Check the mut-clean report file name and look for the paired report, node-only JSON files, edge-only JSON files, and `log.txt` in the two output directories.

- Output graphs are empty.
  - Cause: Molecular interaction reports are missing on one or both sides, so mut-integrate cannot build graph edges.
  - Solution: Add matching EnzyWizard-Interaction reports when graph edges are required; otherwise this is valid non-strict behavior.
